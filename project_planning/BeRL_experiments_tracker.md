# BeRL Experiments — Live Coordination Tracker

**Purpose.** Single source of truth for multiple Claude agents executing BeRL training runs on
a shared cluster. Each agent **claims** a `Not-started` row (set `Status=Processing` + your
`Owner_host`), runs it, and updates `Status`, `WandB link`, `Log path`, and `Results summary`.
Companion docs: `BeRL_paper_plan.md` (rationale/design), `~/workspace/tom_datasets/DATASETS_GUIDE.md`.
Rebuilt to match the current plan (Phase −1 → Phase 0 → Q2 → Q0 → Q1 → Q3 → Q4 → QG).

## Agent protocol (read before claiming)
1. **Claim atomically:** only rows with `Status=Not-started` are claimable — **never touch
   `Backlog` rows** (the user gates those). Pick a `Not-started` row whose dependencies are
   `Completed`. Set `Status=Processing` and `Owner_host=<hostname>` in the same edit before doing
   anything else. If two agents collide, lowest `Exp #` wins; the other reverts.
2. **Respect dependencies (resolve placeholders before launch):**
   - Phase −1 → **stable config** (reward family, KL, clamp, baseline, lr). Cells `=stable(Pm1)`.
   - Phase 0 → **`dcfg_default`** (the winning recipe). Cells `dcfg_default(=P0)`.
   - Q2 → **best reward config** (`power_k`/`ll_min`, actor/frozen). Cells `=Q2best(Q2)`.
   - `=Pm1swp_best(PS)` = the reward+HP config with the best HM-over-last-X from the Phase −1
     one-shot sweep (`PS001–PS098`). Fill concrete values from the winning `PS###` row before
     launching. (Legacy `=Pm1a_best(E001-03)` / `=stable(Pm1)` placeholders now resolve to this.)
3. **Lifecycle:** `Backlog → Not-started → Processing → Training → (In-debug ↔ Training) →
   Completed` (or `Failed`). Use `Awaiting-input` when a user decision is needed; put it in `Notes`.
4. **Naming (RQ + data + params + run index):** the WandB **`Run name`** is self-describing so the
   dashboard alone tells you *what the run investigates, what data, and what params*:
   ```
   <RQ>-<expid>-<data_name>-<model>-<params>-r<N>
   ```
   - `<RQ>-<expid>` = the tracker **`Exp ID`** (the RQ tag is baked into the Exp ID).
   - `<data_name>` = the **`Data config name`** (`dcfg_*` stem).
   - `<model>` = family+size (e.g. `qwen2.5-3b`); `<params>` = key knobs (reward/lr/kl/…).
   - `r<N>` = **run index**, bumped on every *attempt*: if a run crashes and is resubmitted, use
     `-r2`, `-r3`, … so resubmissions never clash in WandB / log filenames. The launcher picks the
     next free `N` (scan `logs/<date>/` + WandB for the base stem).
   - **Test / smoke runs use `RQ=test`** (e.g. `test-gemma_smoke-dcfg_smoke_mix-gemma2-2b-…-r1`).
   The tracker `Run name` column stores the base stem `<RQ>-<expid>-<data_name>`; the launcher
   appends `-<model>-<params>-r<N>` at submit time. `Data config name` = the data-gen YAML + output
   parquet stem (shared across rows with identical data → generate once).
5. **Verify before `Completed`:** eval on `Target evals`, paste `WandB link` + `Log path`, write a
   1–3 line `Results summary` (metric vs baseline + health/hacking notes + downstream implication).

## Execution order (dependency phases)
`Phase −1 (PS001–PS098)` → `Phase 0 (E016–E030)` → `Q2 (E031–E046)` → `Q0 (E047–E053)` →
`Q1 (E054–E061)` → `Q3 (E062–E081)` → `Q4 (E082–E085)` → `QG (E086–E092)`.
**Phase −1 is a one-shot HP+reward sweep** (see §Phase −1 below): **Wave 1** = 96-cell full
factorial on **Qwen2.5-3B** (`PS001–PS096`); **Wave 2** = the same cells on **Gemma-2B** and
**Qwen3-1.7B** (`PS097–PS098`, expanded at gate time), run **only** for cells whose Qwen2.5
counterpart was *not very poor* (not collapsed & HM ≥ baseline). Per the per-family rule, do **not**
assume the Qwen2.5 winner generalizes — Wave 2 keeps all non-terrible cells. Phases 0+ run on
Qwen2.5-3B (workhorse); Gemma rows confirm cross-family. **Batch gating:** only Phase −1 Wave-1
(`PS001–PS096`) starts as `Not-started`; Wave-2 (`PS097–PS098`) and everything else is `Backlog`.
After you review a completed batch, flip the next batch's rows `Backlog → Not-started`.
**Launch mechanism (Phase −1):** `PS###` rows are **claimed and launched individually** like every
other row — they parallelize across agents/nodes via the standard tracker protocol (claim the lowest
`Not-started` `PS###`, set `Status=Processing`+`Owner_host`, then launch). To resolve each cell's
exact knobs and matching `Exp ID`, launch that single cell through the driver in **single-cell mode**:
`ONLY_IDX=<n>` (where `<n>` is the `PS` number, e.g. `ONLY_IDX="7"` runs `PS007`) —
`experiments/phase_stability_sweep.sh` reproduces the sweep enumeration so the generated `EXP_ID`
matches the row exactly. Preview with `BERL_DRY_RUN=1`. A node can run several cells at once by pinning
disjoint GPUs per cell (`GPU_IDS=0,1 ONLY_IDX="7"` …). Run Wave 2 with `FAMILY={gemma,qwen3}`. See
`experiments/README.md` §"Phase −1 sweep". Fixed: 1 epoch (191 steps), `TEST_FREQ=10`, WandB
project `TOM_EXP`.
**Causal gate:** if A1 (E048–E050) does not beat the controls A3-shuffled (E052) and A4-no-CoT
(E053), pause downstream and set A1 to `Awaiting-input`.

## Column meanings
- **Exp #** — global unique id; stable cross-reference handle.
- **Exp ID** — meaningful slug **prefixed with the RQ tag**: `<RQ>-<slug>` (e.g.
  `reward-shaping-Q2_powerk2`, `test-gemma_smoke`). **RQ tag** — theme: `Phase-stability`/
  `data-recipe`/`reward-shaping`/`identifiability`/`generalization`/`interaction`/`cot-style`/
  `model-independence`, or `test` for smoke/test runs.
- **Question investigated** — one-line goal (shared across a group).
- **Model / Size** — family and size (frozen scorer = same family/base).
- **Gen ctx (prompt/resp)** — max prompt / response tokens.
- **KL** — KL-penalty coeff. **Loss/reward type** — `log_prob`|`neg_perplexity`|`power`|
  `rule_based_tom`|`SFT`|`behavior+rule[build]`; mismatch variant for the shuffled control.
  **Loss powers** — `power_k`/`power_ll_min` (ll_min from corpus LL percentiles). **RM mode** —
  `frozen` vs `actor`. **LR** — learning rate. *`=stable(Pm1)`/`=Q2best(Q2)` = use the value from
  that experiment.*
- **Data sources** — training corpus/domains. **Data params** — turn selection, `limit_turn`,
  filter, mixture, `n_conv`, seed, shuffle (first/last turns excluded; held-out = other convs or later turns).
- **CoT prompt var** — `COT_FREEFORM` / `tom_prompt`(`TEMPLATE_FULL`) / `COT_TEMPLATE_NO_*` / `NONE`.
- **Target evals** — `dev` (search rows) or `full suite` (claim rows) = ID/OOD/Applied/Robust/
  Dynamic/Probe/Guardrail/Behavior-PPL.
- **Data config name** — shared data-gen YAML/parquet stem. **Run name** — base WandB stem
  `<RQ>-<expid>-<data_name>`; the launcher appends `-<model>-<params>-r<N>` (run index) to form the
  full WandB run name (see §"Agent protocol" #4).
- **WandB link / Log path / Owner_host / Results summary** — filled by the executing agent.
- **Summary doc** — relative path to the per-experiment write-up markdown (e.g.
  `docs/experiments/PS033.md`); `-` if none yet. Populate when a run completes with analysis.
- **Status** — `Backlog` (gated; only user promotes) · `Not-started` (claimable) · `Processing` ·
  `Training` · `In-debug` · `Awaiting-input` · `Completed` · `Failed`.
- **Notes** — flags: HEADLINE / CONTROL / OUTPUT / EVAL-ONLY, or agent messages.
